Security Review: Anonymous Student Confession Portal

Overview & File Information

This project is a website where students can confess anonymously. Users can send a confession and it will be sent to Telegram. I noticed that when looking through the website source code, some important information and source can be seen by anyone using the browser. I’m still learning web security as a person and I found this interesting because it shows why developers need to be careful with what they put in frontend code.

Since JavaScript is executed in the user browser anyone can open Developer Tools or View Source and see the code. During the review I could see things like API requests and other implementation details. From what Ive learnt you should not store sensitive information on client side JavaScript because users can easily inspect it.

Application Type Anonymous Student Confession Portal
Frontend HTML, CSS, JavaScript
Communication Platform Telegram Bot API

Severity Assessment

Finding Severity
Hardcoded Telegram Bot Token 🔴 High
Client-side API Calls 🟠 Medium
Device Fingerprinting 🟠 Medium
Excessive Personal Data Collection 🟠 Medium
Lack of Privacy Transparency 🟡 Low

1. Static Analysis

I only perform a static analysis for this project, I reviewed the HTML and JavaScript files without testing or interacting with the backend.

Hardcoded Telegram Credentials

While checking the JavaScript code I noticed that the Telegram Bot Token was written directly in the source code.

Because JavaScript is downloaded to every visitor's browser anyone can reveal this token by using:

  • Inspect Element
  • View Page Source
  • Browser Developer Tools

Exposing a bot token may allow unauthorized individual to interact with the Telegram bot depending on its config

Hardcoded Chat IDs

I also found Telegram Chat IDs inside the source code that are used for sending submitted messages.

This reveals where submitted messages are being delivered and exposes internal implementation details that normally should remain server side.

Direct Telegram API Calls

Instead of sending the data to its own backend server first the website sends requests directly to:

https://api.telegram.org/bot<TOKEN>/sendMessage

This means every visitor can observe exactly how messages are transmitted.

Client-side Data Collection

While reading the code I noticed that the website collects several pieces of information from visitors which is suspicous including:

  • Screen resolution
  • Device memory
  • CPU core count
  • Browser language
  • Time zone
  • GPU information (WebGL)
  • Network information
  • Battery status (where supported)
  • Persistent device identifier stored in Local Storage
  • Approximate location from IP lookup
  • GPS coordinates if permission is granted

2. Security Findings

A. Exposure of Secrets

The Telegram Bot Token is embedded directly into client side JavaScript.

Risk: Anyone inspecting the webpage can get the token and potentially misuse the bot.
Recommendation: Bot tokens should always remain on a secure backend server.

B. Client-side Logic Exposure

Since the entire logic executes inside the browser users can easily understand how messages are sent what information is collected, and which Telegram channels receive data.

Key Takeaway: Sensitive operations should not occur entirely on the client side.

C. Personal Data Collection

Although the website is presented as anonymous the code collects multiple pieces of device and browser information before forwarding data to Telegram (fingerprint info, persistent IDs, IP/GPS location, hardware specs, ISP data).

Risk: Collecting this information reduces the level of anonymity users expect.
Recommendation: Developers should clearly disclose what information is collected and ensure compliance with applicable privacy laws and institutional policies.

D. Device Fingerprinting

The application creates a persistent identifier using Local Storage:

localStorage.setItem(...)

Risk: This identifier remain on the device and can associate multiple submissions originating from the same browser.

3. Consideration Privacy

Anonymous submission platforms often encourage users to believe their identity cannot be linked to submissions. However this application collects additional metadata that could potentially be associated with users (device characteristics, network info, fingerprinting, persistent IDs, location data).

Developers should ensure users are informed about any collected data and follow applicable privacy requirements.

5. Conclusion

From this project I learned that storing secrets in frontend code is not a good practice because anyone can inspect the website and view them. I also noticed that the website collects a lot of information from users before sending messages to Telegram even though it presents itself as anonymous.

Overall this was a good learning experience for me. It helped me understand common security mistakes in web applications and showed me why developers should protect sensitive information and be transparent about the data they collect.
